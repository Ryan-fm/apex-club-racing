## 优先处理的技术问题

### P1：性能记录无法反映严重慢帧

[game.js:644](/Users/mac/Downloads/antigrav_racer/game.js:644) 先执行 `Math.min(clock.getDelta(), .08)`，随后把截断后的值传给 `perf.beginFrame`。因此记录最大只能到 80ms，`>100ms` 计数永远无法识别真实长帧。本次按实际接线方式复现：180ms 输入被记为 80ms，verySlow 为 0。

[runtime/performance.js:119](/Users/mac/Downloads/antigrav_racer/runtime/performance.js:119) 每帧排序计算统计；样本达到上限 720 后，`samples.length % 12 === 0` 每帧都成立，面板会每帧读取存储并更新文本。统计还混合首页、暂停和比赛，缺少按测试段开始/结束重置。保存报告不包含完整输入轨迹、语言、构建和整段 renderer 统计；render 的 CPU 调用时长也不是 GPU 时长。

处理：将原始帧间隔和受限模拟 dt 分离；按测试段和状态收样；用独立帧计数或时间间隔低频汇总；存储读取移到用户操作或低频更新。补同设备、同配置、同输入至少三次的原版/候选版报告，再判断优化收益。

### P1：体验段可能污染正式圈速和幽灵记录

[game.js:303](/Users/mac/Downloads/antigrav_racer/game.js:303) 将起点移到 0.245；[game.js:687](/Users/mac/Downloads/antigrav_racer/game.js:687) 仍使用正式地图/车型的最佳圈速存储键；[game.js:715](/Users/mac/Downloads/antigrav_racer/game.js:715) 在有效首圈后会写入记录。

本次直接调用实际 `recordLap` 规则，从 0.245 跑到 1：`valid: true`，第一个分段成绩为 0，跳过前 24.5% 的不完整首圈被接受。这是规则级复现，未通过浏览器完整跑完并污染用户真实记录。

处理：体验段采用独立挑战 ID/存储键，或明确禁止写入正式成绩；首个不完整圈不得提交正式纪录。独立记录不能只靠 URL 入口名称区分。

### P1：阶段 A 的验收证据不完整

输入和 HUD 已提取，粒子重复更新已有减少，但 [game.js:359](/Users/mac/Downloads/antigrav_racer/game.js:359) 到 `animateCraft` 仍位于模拟子步中。慢帧多个物理子步会重复更新姿态、矩阵和车轮；教学也会在子步内写 DOM。真正的 simulation/presenter 边界、固定输入回放和 A/B 报告尚未建立。

因此应将上一轮结论修正为“阶段 A 部分实现，尚未通过出口验收”。67 项测试说明已覆盖的规则通过，不能推出完整驾驶与性能均合格。

### P2：默认规则和维护文档不一致

README 仍写 Space 漂移、Shift 氮气及松开漂移直接变小喷，与当前 Shift 漂移、Ctrl 氮气、W 触发小喷不一致。交接文档指出了这点，但面向使用者的入口说明仍应同步。CSS 中多轮断点覆盖与 `!important` 较多，后续手机调整应收敛到单一布局规则，降低回归风险。
