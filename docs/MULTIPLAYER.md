# 好友房基础功能

通用多人房在 `main` 开发，平台接入遵循根目录 `AGENTS.md`。本版本不依赖 Toy SDK。

## 本地运行

```sh
npm install
npm run build
npm run start:multiplayer
```

打开 `http://localhost:8082/race.html`，点击好友房，输入昵称创建房间。其他玩家输入房间码或打开邀请链接加入。局域网测试使用电脑的局域网 IP 替换 localhost，各设备均访问 8082 端口。

房间支持 2–4 名真实玩家，人数由服务端限制。房主选择赛道，所有玩家准备后开始三圈比赛；支持漂移、迷你加速和氮气。当前版本不加入 AI、车间碰撞、EMP 或赛道道具。多人赛结果不会写入单人排行榜。

服务器运行共享驾驶模拟，每秒 60 次更新、20 次状态广播。客户端预测自己的驾驶并按服务端确认纠正，其他车辆平滑显示。临时断线保留位置 20 秒并尝试重连；刷新页面会使用当前标签页保存的私有恢复令牌重新加入；退出房间后清除。房主离线后转交房主权限。首位完赛后等待 20 秒结算，整场最长 10 分钟；主动退赛标记 DNF。

## Vercel 正式部署

正式站点为 `https://apex-club-racing.vercel.app/race.html`。前端自动使用同源 `wss://apex-club-racing.vercel.app/api/rooms`，入口 `api/rooms.js` 导出 Node HTTP / WebSocket 服务，已启用 Fluid Compute。

房间、成员、恢复身份、驾驶状态和输入队列保存在共享 Redis，环境变量为 `REDIS_URL` 或 `KV_URL`，只能配置在服务端。Redis 部署在 iad1，与 Vercel 函数同区域。每个房间通过带随机令牌的租约执行模拟，并以 Lua 原子提交状态、消费输入和广播；过期执行器不能覆盖新的状态。不同函数实例的玩家可以加入同一房间。Redis Pub/Sub 传送状态快照和请求结果，恢复令牌不会进入公共快照。

Vercel 函数最长运行 300 秒，连接关闭时客户端重新连接并通过私有令牌恢复房间。实例异常退出时，12 秒的在线租约到期后释放连接，断线席位再保留 20 秒。比赛状态不依赖某台本地电脑或单个函数进程。

`/api/rooms/health` 返回房间服务和共享存储健康状态。没有 Redis 配置时返回 503，不会接受无法同步的房间。当前共享存储使用免费方案，并关闭自动升级；达到供应商额度时需评估扩容，不能将免费额度当作无限容量。

## 独立 Node 服务

`server/multiplayer.js` 仍用于本地或持续运行的独立 Node 服务，端口可用 `PORT` 配置，提供 `/ws` 和 `/health`。此入口的房间在单个进程内，不能用于多副本部署。服务端用 `MULTIPLAYER_ALLOWED_ORIGINS` 设置允许来源，多个来源以逗号分隔。需要使用独立公网服务时，构建前指定 `MULTIPLAYER_WS_URL=wss://rooms.example.com/ws`。

Toy 身份和邀请分享只在 `codex/toy-*` 分支接入，沿用上述通用房间协议。

## 验证

`npm test` 包含真实四 WebSocket 客户端同步、人数限制、准备与房主权限、断线恢复、输入验证、客户端预测、四人三圈完赛和一致排名测试。

跨实例集成测试使用真实 Redis：`REDIS_TEST_URL=redis://127.0.0.1:6387 npm test`。测试包括双网关四人联机、第五人拒绝、换网关重连、租约隔离和断线清理。
