# 每周活动与车手成长

通用功能在 main。平台适配只依赖 onlineClub 的 progress、claimReward、saveGarage 接口；不导入 Toy SDK。Toy 分支使用 B站云存储，正式版使用现有 Supabase 用户会话和数据库。

## 默认规则

- 周一北京时间 00:00 重置任务计数与领取记录，永久解锁的车辆与涂装保留。
- COMET / APEX 为 C 级初始车；VINTAGE 为 B 级（15 分钟），SLIDE 为 B 级（30 分钟），BOLT 为 A 级（60 分钟），TITAN 为 S 级（120 分钟）。等级表达解锁门槛；不额外强化现有车辆物理参数。
- 驾驶时长统计移动中的比赛，排除大厅、暂停、隐藏页面、教学和诊断回放。好友房驾驶计入时长，完赛任务目前只统计有效的单人三圈比赛。
- 每周 10 分钟领取熔金流线，30 分钟领取极光脉冲，60 分钟领取冠军之翼；完成 3 场有效单人三圈比赛领取赛道格纹。每项每周领取一次，同时分别获得 20、30、40、60 活动积分，拥有涂装后仍可每周领取积分。积分达到 100/300/600 获得俱乐部/精英/传奇车手称号，不提升赛车性能。
- 游客使用独立本地进度；登录后以账户云存档为准，不把可修改的游客记录导入账户。
- 活动入口显示可领取数量；车库显示下一车辆门槛，锁定车辆可预览。结果页提供活动入口，领奖不会自动装备。

## 数据库与上线

迁移：supabase/migrations/202610110001_progression.sql。2026-10-11 已应用到生产数据库，并与新版前端一起发布。线上验证通过账户进度读取、车库配置保存与恢复、未完成任务禁止领取、排行榜外观字段和私有表访问限制。

club_progress 存累计驾驶时长、周进度、领取记录、永久涂装和车库配置。表对公开角色关闭读写，仅经过现有 token 验证的 RPC 访问。heartbeat 每次最多 60 秒，并限制在服务端经过时间以内；receipt 使重试不重复计时。任务领取在锁行事务中校验、幂等处理。

完赛任务复用完整三圈的轨迹校验；同一轨迹不重复计数。服务器阻止未解锁车辆或涂装提交榜单。最佳成绩同时保存当次整车外观快照；旧记录继续用原车型的默认外观展示。

驾驶 heartbeat 仍由客户端报告，限制服务端时间不能完全证明真人驾驶。

本地 SQL 验证使用临时 PGlite 数据库执行迁移，覆盖未解锁奖励/车辆、重复 heartbeat/领取/成绩、周重置、整车快照与私有表权限；其中 digest 使用测试替身，不替代生产 pgcrypto。浏览器验证覆盖车库锁定、任务领取、奖励装备与活动展示。

## Toy 平台限制

SDK 原生 submitScore 只发送 board 与 score；getRankList 不带整车外观，getCloudStorage 也无法读取其他车手存档。因此 Toy 存档能保存自己的成长与涂装，但全榜整车展示需要额外公开展示服务。未决定或实现这个服务前，不用虚构车辆信息填充其他玩家榜单。

Toy 存档写入应串行化并保留有限 receipt；SDK 没有事务/CAS，多设备同时游戏仍可能出现后写覆盖。Toy 客户端云存档也不具备正式版 RPC 的服务端领奖校验能力。
